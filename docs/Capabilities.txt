How the software was built
----------------------------

The overall solution spans three complementary layers.

The thin Python SDK is packaged with setuptools for installation from the NERSC GitHub repository (Python 3.12 or newer). It uses an HTTP client over TLS to call the REST API, obtains SFAPI bearer tokens from the standard token endpoint, and exposes a programmatic client plus a CLI that dispatches subcommands for queues and jobs. Tabulate supports table output; Qiskit is used so quantum circuits can be serialized with QPY and embedded in job payloads where required.

The server deployment is implemented as a FastAPI application with SQLAlchemy and a PostgreSQL database. NERSC SFAPI bearer-token authentication identifies callers, while NERSC LDAP groups grant ordinary, operator, and administrator access. Job ownership and audit attribution use NERSC usernames directly; AQDrop does not maintain local user accounts. Job and queue endpoints persist state through CRUD layers against PostgreSQL.

Operator-side tooling runs on machines adjacent to hardware or simulators. Daemon scripts poll or drive workflows that fetch queued work through this SDK, execute circuits with Qiskit, or drive lab-specific quantum control stacks before posting results through the API. That runtime, its hardware dependencies, and the operator container are maintained separately in `NERSC/aqdrop-operator`.


Capabilities
------------

• Authenticated access to the central service using SFAPI bearer tokens.

• LDAP authorization: `aqdrop_users`, `aqdrop_operator`, and `aqdrop_admin` membership controls access without local account management.

• Queue management: define queues with capacity, topology limits, type, and lifecycle state; list and filter queues for monitoring.

• Job management: submit structured job input (including Qiskit circuits with shot metadata when using the SDK); query jobs by id, queue, owner, or status; retrieve results; check status; cancel or dispatch updates subject to permissions.

• A command-line interface for user job operations and authorized queue administration.

• A stable SDK consumed by the separate operator runtime when it pulls queued work and posts results.


Intended end-use
----------------

The software supports the Advanced Quantum Testbed (AQT) management model: a single service mediates access to constrained quantum execution resources rather than exposing hardware ad hoc. Researchers and application authors use the Python SDK to submit work, monitor queues, and inspect outcomes. Administrators configure queues, while operators run the execution side that bridges queued API jobs to simulators or controlled hardware. NERSC LDAP administrators manage role membership outside AQDrop. Typical deployment aligns with institutional high-performance computing environments while the same components can be adapted for laboratory or containerized installs.
